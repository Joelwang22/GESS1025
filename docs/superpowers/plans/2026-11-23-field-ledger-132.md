# Field Ledger 132 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the agreed Field Ledger 132 reading interface without losing any checklist content or creating false workflow semantics.

**Architecture:** Keep VitePress as the static shell. Extend the existing generator to emit faithful task markup and derived catalog/route metadata, then add a thin local theme layer for station headers, tracings, navigation lookup, command controls, and responsive ledger styling. Core content and routes remain server-rendered static HTML.

**Tech Stack:** Node.js 22, VitePress 2 alpha, Markdown-it/Shiki hooks already supplied by VitePress, Vue 3 theme components, Node test runner, headless Chromium.

**Spec:** `docs/superpowers/specs/2026-11-23-field-ledger-132-design.md`

## Global Constraints

- Preserve all 145 tasks, 28 modules, exact source commands, explanations, routes, ordering, version, and provenance.
- Add no runtime network dependency, backend, analytics, telemetry, progress, completion state, target storage, credentials, command execution, or inferred success semantics.
- Keep source-derived navigation honest; do not introduce a curated observation matrix or invented recommendation.
- Keep VitePress local search, GitHub Pages base `/checklist/`, and exhaustive local-link validation working.
- Body text stays at least 16px and the tested pages must not create document-level horizontal overflow.
- New behavior follows red-green-refactor: add a focused failing test, verify the expected failure, implement, then run the complete suite.
- Use `apply_patch` for file edits and preserve unrelated user work.

## Review Focus

- Inline code containing `<...>` must render and copy literally once, while Vue/HTML syntax remains inert.
- Compound and abbreviated task references must link every known destination without linking terminal states or touching fenced commands.
- Direct task URLs must retain module execution context so Kali-versus-target command boundaries remain visible.
- Long commands and tables must remain readable at 390px without causing page-level horizontal overflow or ambiguous soft wraps.
- Derived route and backlink UI must never imply completion, success, preference, or source-authored guidance.
